# Anti-Spoofing Engine v2 — Fix glossy/bad-light replay false accepts (keep existing models)

## Root cause (verified in code)

The reported bug — screen replay accepted as real ~1/20 times under glare/bad light — is a decision-layer failure, not model weakness (measured per-frame AUC 0.893 against the hardest attack):

1. **Compromised frames still vote.** The quality gate (`LivenessFusion.gate()`, LivenessFusion.kt:186) checks only mean face luma (≤240) and blur. A glossy washed-out frame passes, and the MiniFASNet ensemble — texture-blind under glare — outputs low attack prob. The ANTI_SPOOF cue is symmetric around centre 0.25, so those frames each contribute ~**−1.15 nats toward LIVE** (LivenessFusion.kt:477). Two such frames reach the −2.0 accept bound; `LIVE_CONFIRMED` then stops sampling.
2. **The SPECULAR cue never fires**: it requires luma ≥ 244 (`SPECULAR_LUMA`, LivenessCues.kt:875), unreachable under auto-exposure — documented at LivenessFusion.kt:440-442. Gloss is invisible to the engine.
3. **Single effective cue**: only ANTI_SPOOF carries weight, and both ensemble models are same-family MiniFASNets fed identical raw crops — they fail together under glare. `ATTACK` is unreachable (needs 2 corroborating cues).

Per your choices: **strictly passive**; all mechanisms implemented now with conservative defaults + `TODO-CALIBRATE` markers, fitted later from captures via the existing harness. **Existing models kept** — retraining demoted to a deferred contingency.

## Phase 1 — Compromised frames must not vote (directly kills the reported bug)

Files: `LivenessCues.kt`, `LivenessFusion.kt` (gate), `FacePipeline.kt` (logging).

1. **Glare metric that actually fires**: add `highlightCoverage` (fraction of face-region pixels above a reachable luma) to `FrameQuality`, and fix `SPECULAR_LUMA` (244 → conservative ~232, TODO-CALIBRATE) so the existing compactness×coverage blob logic can measure. Extend `QUALITY`/`GATED` log lines with the new fields (refused-frame logging pattern already exists).
2. **Glare gate**: `highlightCoverage > MAX_HIGHLIGHT_COVERAGE` → refuse the frame with `LESS_GLARE` guidance instead of scoring it. A frame where the model is blind is absence of evidence, not live evidence.
3. **Exposure-transient abstention**: track previous scored frame's faceLuma; if |Δ| > `MAX_LUMA_STEP`, abstain that tick (auto-exposure ramps currently produce washed-out frames that vote live).
4. **High-ISO/dim refusal**: add a noise proxy to `FrameQuality` (high-frequency energy ratio); refuse frames in the sensor-noise regime with `MORE_LIGHT`. Addresses the known dim-light overlap (genuine 0.346 vs attack 0.271) in both directions: dim genuine stops scoring attack-like, dim replay stops scoring live-like; both end OPEN with actionable guidance.

All thresholds: conservative defaults, `TODO-CALIBRATE`, sweepable by extended `--gate-sweep`.

## Phase 2 — Decision-rule hardening (`LivenessFusion.kt`)

1. **Minimum scored ticks before LIVE**: verdict stays OPEN until `MIN_TICKS_TO_ACCEPT` (default 5) — kills the 2-glossy-frames accept; costs ~200 ms median latency in good light.
2. **Ambiguity dead-band / confidence-scaled LLR**: ANTI_SPOOF's per-frame LLR scales with ensemble confidence (max softmax) plus a dead-band around the centre, so ambiguous glossy frames contribute ~0 instead of −1.15 nats. Strong disagreement between the two models also demotes a frame to low-confidence.
3. **Accumulator reset on strong attack evidence**: a good-quality frame with attackProb > `ATTACK_RESET_PROB` (default 0.75) resets accumulated `total` toward 0 — erases spurious live evidence without ever emitting an ATTACK verdict (not the deleted `hasAttackSignal` veto; it rejects no one).

## Phase 3 — Restore cue independence (keep both existing TFLite models)

1. **SPECULAR as the second separating cue**: with Phase 1's threshold fix it can fire; stays one-sided (accuse-only). Side-lit glossy replay should accrue corroborating evidence, making `ATTACK` reachable — the fix the code itself calls for (LivenessFusion.kt:474).
2. **Contrast-normalized second input**: feed V1SE a per-crop contrast-normalized (mean/σ stretch) 80×80 crop while V2 gets raw. The ensemble becomes diverse in failure modes — glare kills raw-input texture but not normalized. Update `scripts/run_golden_tests.py` (per-model input contract).
3. **Temporal flicker cue (experimental, weight 0)**: luminance micro-variance of fixed face points across consecutive analyzer frames at full frame rate (Y-plane only, cheap) — captures display refresh/rolling-shutter beating. Compute + log only; enable if captures show separation.
4. **Higher-res analysis option (perf-flagged, default off)**: allow 1280×720 ImageAnalysis for the moiré band-pass; moiré can't survive 640×480 downsampling (documented in-code), so this is that cue's only path.

## Risks / trade-offs

- Strictly passive means dim/glossy conditions end in guidance retry loops more often — the cost of never scoring compromised frames; mitigated by actionable LESS_GLARE/MORE_LIGHT messaging.
- Min-ticks + dead-band add ~200–300 ms to good-light acceptance.
- Conservative defaults before calibration are deliberately err-toward-refusal: expect more OPEN verdicts until the capture session tunes the constants.
